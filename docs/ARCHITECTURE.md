# Architecture

Deadline Reminder is a Manifest V3 extension written in plain JavaScript (ES modules),
HTML and CSS. Vite bundles each extension page separately; there are no runtime
dependencies and no server.

## Folder structure

```text
public/                  copied unchanged into dist/
  manifest.json          MV3 manifest (permissions: storage, alarms, notifications)
  theme-boot.js          tiny non-module script that applies a saved theme before paint
  icons/                 PNG icons (generated by scripts/generate-icons.mjs)
src/
  background/
    service-worker.js    event-driven: schedules alarms, shows notifications
  popup/                 popup.html / popup.js / popup.css
  dashboard/             dashboard.html / dashboard.js / dashboard.css
  components/            DOM building blocks shared by both pages
    assessment-card.js   card, due badge, priority indicator, keyed list renderer
    deadline-form.js     add/edit form (basic fields + "Advanced options")
    deadline-dialogs.js  add/edit, details, delete-with-undo, complete-with-undo flows
    import-panel.js      document picker and "in development" import panel
    settings-panel.js    settings dialog, backup/restore
    dialog.js, toast.js, icons.js
  models/
    assessment.js        the deadline model (pure functions)
    settings.js          settings defaults, categories, normalisation
  services/
    storage.js           the only module that touches chrome.storage.local
    migrations.js        schema versions and upgrade steps
    assessments.js       create/update/delete/complete/attach operations
    query.js             deadline state, filtering, sorting, summaries (pure)
    reminders.js         reminder times and chrome.alarms syncing (pure + thin adapter)
    documents.js         file checks and extraction comparison/merge (pure)
    backup.js            JSON export/import
    theme.js, app.js     page bootstrap and theme switching
  utils/
    dates.js             calendar maths and time-zone conversion
    validation.js        form/backup input validation
    dom.js               safe element creation, debounce
  styles/
    tokens.css           design tokens (light-dark() pairs)
    shared.css           shared components
scripts/
  verify-build.mjs       post-build checks (files exist, no inline/remote code, permissions)
  generate-icons.mjs     dependency-free PNG icon generator
  smoke-test.mjs         optional headless-browser test of the built extension
tests/                   Vitest unit tests (+ helpers/chrome-mock.js)
```

Layers depend only downwards: pages → components → services → models/utils. Models,
`query.js`, `reminders.js` (apart from `syncAlarms`), `documents.js`, `backup.js`,
`migrations.js`, `dates.js` and `validation.js` are pure and tested without a browser.

## Data flow

```text
 popup / dashboard ──(service call)──▶ assessments.js ──▶ storage.js ──▶ chrome.storage.local
        ▲                                                                      │
        └──────────── app.js listener ◀── chrome.storage.onChanged ◀───────────┤
                                                                               │
                         service-worker.js ◀── chrome.storage.onChanged ◀──────┘
                               │ computeReminders + syncAlarms
                               ▼
                         chrome.alarms ──onAlarm──▶ chrome.notifications
```

Pages never patch their own state after a write. Every write goes to storage, and every
open page (and the service worker) reacts to `chrome.storage.onChanged`. This keeps the
popup, any open dashboards and the reminder schedule consistent with a single source of
truth.

Writes use read-modify-write (`storage.updateAssessments`) with a fresh read each time,
so two open pages do not overwrite each other with stale copies. A write is skipped
when nothing changed.

## Storage

All data lives in `chrome.storage.local`:

| Key             | Value                                             |
| --------------- | ------------------------------------------------- |
| `schemaVersion` | `1`                                               |
| `assessments`   | array of assessment objects (manual and imported) |
| `settings`      | settings object                                   |

- `storage.init()` runs once per page/worker: it reads everything, runs migrations,
  drops records that cannot be repaired, and writes back only if something changed.
- **Migrations** (`services/migrations.js`) are pure functions, one per version.
  Version 0 is the shape sketched in the original Deadline Planner extension plan
  (`due`, `module`, `time`, `"40%"` weighting, `created_at`), so early data upgrades
  cleanly.
- Data from a **newer** schema version is left untouched and the storage becomes
  read-only, so an older build never damages it.
- Errors are wrapped in `StorageError` with a readable message (for example, quota full).
- Document files are **not** stored. `chrome.storage.local` (10 MB) holds JSON only.
  `unlimitedStorage` is not requested.

## Assessment model

One JSON-compatible object per deadline. Manual and document-based deadlines share it;
`sourceType` records how a deadline was created. Unknown values are `null`, never guessed.

| Field                    | Type                                           | Notes                                                                |
| ------------------------ | ---------------------------------------------- | -------------------------------------------------------------------- |
| `id`                     | string (UUID)                                  |                                                                      |
| `title`                  | string                                         | required, ≤ 200 chars                                                |
| `category`               | string                                         | built-in id (`assignment`, `exam`, …) or custom slug                 |
| `moduleName`             | string \| null                                 |                                                                      |
| `moduleCode`             | string \| null                                 |                                                                      |
| `dueDate`                | `"YYYY-MM-DD"`                                 | required; a calendar date, never a UTC timestamp                     |
| `dueTime`                | `"HH:MM"` \| null                              | null = due by the end of the day                                     |
| `timeZone`               | IANA zone                                      | default `Europe/Dublin` (from settings)                              |
| `weighting`              | number 0–100 \| null                           | percent                                                              |
| `priority`               | `low` \| `medium` \| `high`                    |                                                                      |
| `description`            | string \| null                                 | description or requirements                                          |
| `notes`                  | string \| null                                 |                                                                      |
| `submissionUrl`          | http(s) URL \| null                            |                                                                      |
| `checklist`              | `{ id, text, done }[]`                         | deliverables                                                         |
| `reminderOffsets`        | number[] \| null                               | minutes before due; null = use settings defaults                     |
| `estimatedMinutes`       | integer \| null                                |                                                                      |
| `tags`                   | string[]                                       |                                                                      |
| `completed`              | boolean                                        |                                                                      |
| `completedAt`            | ISO timestamp \| null                          |                                                                      |
| `sourceType`             | `manual` \| `pdf` \| `docx`                    | how it was created                                                   |
| `sourceDocument`         | `{ id, name, type, size, attachedAt }` \| null | linked brief; metadata only; `id` is the source document ID          |
| `extractionConfidence`   | `high` \| `medium` \| `low` \| null            | overall confidence of an extraction                                  |
| `userConfirmed`          | boolean                                        | always true for manual entries                                       |
| `confirmedFields`        | string[]                                       | fields the user typed or approved; protected from silent replacement |
| `createdAt`, `updatedAt` | ISO timestamps                                 |                                                                      |

`normalizeAssessment` turns anything (stored data, backups, migrated records) into this
shape or returns `null`. `applyChanges` returns the same object when nothing changed,
which lets callers skip storage writes.

## Dates and time zones

- Calendar maths (`addDays`, `daysBetween`) works on UTC day numbers built from the
  `YYYY-MM-DD` parts. `new Date('2026-12-11')` is never used, because it means UTC
  midnight and shows as 10 December west of UTC.
- "Today" is computed in the deadline's own time zone with `Intl.DateTimeFormat`.
- `zonedDateTimeToEpoch` converts a wall-clock time in a zone to an instant, computing
  the offset twice to handle daylight-saving changes.
- A date-only deadline is overdue from the next day; a timed one from that minute.

## Reminders

`computeReminders` produces the full set of alarms that should exist; `syncAlarms`
creates the missing ones and clears stale ones (only alarms named `dr:<id>:<offset>`).
The service worker runs this on install, browser start-up and every storage change, so
edits, completions and settings changes reschedule automatically.

- Whole-day offsets on a date-only deadline fire at the reminder time (default 09:00) on
  that day; otherwise the offset is subtracted from the due time (23:59 for date-only).
- Past reminders and completed deadlines are skipped; at most 400 alarms are kept
  (Chrome allows 500 per extension).
- Clicking a notification opens the dashboard at that deadline.

## Documents (Stage 1 preparation)

- `validateDocumentFile` accepts `.pdf` and `.docx` only, checks the file signature
  (`%PDF` / ZIP `PK`), rejects `.docm`, empty files and files over 30 MB.
- A linked document is stored as metadata only. No parser is bundled; the manual flow
  never loads one.
- `compareWithExtraction` and `applyDocumentChanges` define how Stage 2 will merge
  extracted values into an existing deadline: differences are listed, empty fields are
  pre-selected, fields in `confirmedFields` are never pre-selected, and notes,
  completion, checklist progress and reminder preferences are always preserved. New
  deliverables are appended to the checklist.

## UI

- Built with small DOM helpers (`h()`); all text is set with text nodes. Nothing uses
  `innerHTML`, and a test enforces this.
- Lists render with one delegated click handler. Cards are cached by record object and
  only rebuilt when the record or the day changes.
- Dialogs use native `<dialog>` with `showModal()` (focus trap, Escape, inert
  background), labelled titles and focus restoration.
- Colours are `light-dark()` token pairs. `<html data-theme>` forces light or dark;
  without it the system preference applies. `prefers-reduced-motion` disables motion.
- Urgency is shown with text and an icon as well as colour.

## Security

- MV3 CSP: `script-src 'self'; object-src 'self'`. No inline scripts (verified after
  each build), no remote code, no `eval`.
- Submission links must be `http(s)`; they open with `rel="noopener noreferrer"`.
- Backups are parsed as JSON and normalised record by record before they are written.

## Design decisions

| Decision                       | Reason                                                                            |
| ------------------------------ | --------------------------------------------------------------------------------- |
| No framework                   | The UI is small; plain modules keep the popup fast and the bundle tiny.           |
| One `assessments` array        | Simple, atomic writes; expected data size is small (hundreds of items).           |
| `light-dark()` tokens          | One token set for both themes; needs Chrome/Edge 123+ (`minimum_chrome_version`). |
| `alarms` + `notifications` now | Reminders are a core requirement for manual deadlines; no host access is needed.  |
| Calendar date strings          | Avoids the classic UTC off-by-one-day bug for date-only deadlines.                |
| Metadata-only document links   | Keeps storage small and avoids holding file contents before extraction exists.    |
