# Architecture

Deadline Reminder is a Manifest V3 extension written in plain JavaScript (ES modules),
HTML and CSS. Vite bundles each extension page separately. The only runtime
dependencies are PDF.js and Mammoth.js, used on the import page only. There is no server.

## Folder structure

```text

  manifest.json          MV3 manifest (permissions: storage, alarms, notifications)
  theme-boot.js          tiny non-module script that applies a saved theme before paint
  icons/                 PNG icons (generated by scripts/generate-icons.mjs)
src/
  background/
    service-worker.js    event wiring only (install, start-up, storage, alarms, notifications)
    reminder-runner.js   reconcile, alarm and notification-action handling (APIs injected)
  popup/                 popup.html / popup.js / popup.css
  dashboard/             dashboard.html / dashboard.js / dashboard.css (incl. document library)
  import/                import.html / import.js / import.css: import queue and review page
  extraction/            the extraction engine (pure, no browser APIs)
    date-parser.js       dates, times, missing years, weekday-only, daylight saving
```

Layers depend only downwards: pages → components → services → models/utils. Models,
`query.js`, `reminders.js` (apart from `syncAlarms`), `documents.js`, `duplicates.js`,
`backup.js`, `migrations.js`, `dates.js`, `validation.js` and everything in
`extraction/` are pure and tested without a browser. `documents/` readers take the
PDF.js or Mammoth module as a parameter, so tests run them in Node with real files.

### Code splitting

| Page        | JavaScript loaded up front | Loaded later                                                                                         |
| ----------- | -------------------------- | ---------------------------------------------------------------------------------------------------- |
| Popup       | ~48 KB                     | dialogs and card menu on first use                                                                   |
| Dashboard   | ~106 KB                    | nothing                                                                                              |
| Import page | ~86 KB                     | PDF.js (~432 KB + 1.24 MB worker) on the first PDF; DOCX worker with Mammoth (~309 KB) per Word file |

`scripts/verify-build.mjs` follows every static and dynamic import from the popup and
dashboard and fails the build if either can reach PDF.js or Mammoth.

## Data flow

```text
 popup / dashboard ──(service call)──▶ assessments.js ──▶ storage.js ──▶ chrome.storage.local
        ▲                                                                      │
        └──────────── app.js listener ◀── chrome.storage.onChanged ◀───────────┤
                                                                               │
                         service-worker.js ◀── chrome.storage.onChanged ◀──────┘
                               │ computeReminders + syncAlarms
                               ▼
                         chrome.alarms ──onAlarm──▶ chrome.notifications
```

Pages never patch their own state after a write. Every write goes to storage, and every
open page (and the service worker) reacts to `chrome.storage.onChanged`. This keeps the
popup, any open dashboards and the reminder schedule consistent with a single source of
truth.

Writes use read-modify-write (`storage.updateAssessments`) with a fresh read each time,
so two open pages do not overwrite each other with stale copies. A write is skipped
when nothing changed.

### Import flow

```text
 import page ── File ──▶ pipeline.processFile ──▶ file-checks (basics, structure)
                               │                       │
                               │            sha256 (Web Crypto)
                               ▼
          PDF: loadPdfjs() → pdf-reader (PDF.js worker)   DOCX: docx-worker (ZIP checks → Mammoth)
                               │
                               ▼
                 extraction/engine → candidates + evidence
                               │
          duplicates.classifyImport(hash, candidates, library)
                               │
                 import-review (user edits and confirms)
                               │
         imports.saveReviewedImport → storage.updateLibrary (one write)
```

## Storage

All data lives in `chrome.storage.local`:

| Key             | Value                                                               |
| --------------- | ------------------------------------------------------------------- |
| `schemaVersion` | `3`                                                                 |
| `assessments`   | array of assessment objects (manual and imported)                   |
| `settings`      | settings object (incl. `importLimits`, `retainDocumentFiles`)       |
| `documents`     | document library records (metadata + evidence, no file contents)    |
| `reminderState` | `{ lastCheckedAt, fired, snoozes, history }` (reminder bookkeeping) |

- `storage.init()` runs once per page/worker: it reads everything, runs migrations,
  drops records that cannot be repaired, and writes back only if something changed.
- **Migrations** (`services/migrations.js`) are pure functions, one per version.
  Version 0 is the shape sketched in the original Deadline Planner extension plan
  (`due`, `module`, `time`, `"40%"` weighting, `created_at`), so early data upgrades
  cleanly. Version 2 (Stage 2) adds `documents` and the new assessment fields with empty
  values. Version 3 (Stage 3) adds `pinned` and `isDemo` to deadlines.
- `storage.updateLibrary` writes deadlines and library records in one `set()` call, so an
  import never leaves a deadline pointing at an unsaved record.
- Data from a **newer** schema version is left untouched and the storage becomes
  read-only, so an older build never damages it.
- Errors are wrapped in `StorageError` with a readable message (for example, quota full).
- Document files are **not** stored in `chrome.storage.local` (10 MB, JSON only).
  When the user enables **Keep original files**, they go to IndexedDB
  (`services/file-store.js`). `unlimitedStorage` is not requested.

## Assessment model

One JSON-compatible object per deadline. Manual and document-based deadlines share it;
`sourceType` records how a deadline was created. Unknown values are `null`, never guessed.

| Field                    | Type                                           | Notes                                                                   |
| ------------------------ | ---------------------------------------------- | ----------------------------------------------------------------------- |
| `id`                     | string (UUID)                                  |                                                                         |
| `title`                  | string                                         | required, ≤ 200 chars                                                   |
| `category`               | string                                         | built-in id (`assignment`, `exam`, …) or custom slug                    |
| `moduleName`             | string \| null                                 |                                                                         |
| `moduleCode`             | string \| null                                 |                                                                         |
| `dueDate`                | `"YYYY-MM-DD"`                                 | required; a calendar date, never a UTC timestamp                        |
| `dueTime`                | `"HH:MM"` \| null                              | null = due by the end of the day                                        |
| `timeZone`               | IANA zone                                      | default `Europe/Dublin` (from settings)                                 |
| `weighting`              | number 0–100 \| null                           | percent                                                                 |
| `priority`               | `low` \| `medium` \| `high`                    |                                                                         |
| `description`            | string \| null                                 | description or requirements                                             |
| `notes`                  | string \| null                                 |                                                                         |
| `submissionUrl`          | http(s) URL \| null                            |                                                                         |
| `checklist`              | `{ id, text, done }[]`                         | deliverables                                                            |
| `reminderOffsets`        | number[] \| null                               | minutes before due; null = use settings defaults                        |
| `estimatedMinutes`       | integer \| null                                |                                                                         |
| `tags`                   | string[]                                       |                                                                         |
| `submissionMethod`       | string \| null                                 | e.g. "Moodle"                                                           |
| `wordCount`              | string \| null                                 | display text, e.g. "2,000–2,500 words"                                  |
| `groupSize`              | string \| null                                 | display text, e.g. "3–4 students"                                       |
| `instructions`           | string[]                                       | important instructions                                                  |
| `markingCriteria`        | string[]                                       |                                                                         |
| `relatedDates`           | `{ id, label, date, time, note }[]`            | presentation, exam, feedback, release, revision, late submission, other |
| `completed`              | boolean                                        |                                                                         |
| `completedAt`            | ISO timestamp \| null                          |                                                                         |
| `sourceType`             | `manual` \| `pdf` \| `docx`                    | how it was created                                                      |
| `sourceDocument`         | `{ id, name, type, size, attachedAt }` \| null | linked brief; `id` is the document library record id                    |
| `extractionConfidence`   | `high` \| `medium` \| `low` \| null            | overall confidence of an extraction                                     |
| `userConfirmed`          | boolean                                        | always true for manual entries                                          |
| `confirmedFields`        | string[]                                       | fields the user typed or approved; protected from silent replacement    |
| `createdAt`, `updatedAt` | ISO timestamps                                 |                                                                         |

`normalizeAssessment` turns anything (stored data, backups, migrated records) into this
shape or returns `null`. `applyChanges` returns the same object when nothing changed,
which lets callers skip storage writes.

## Dates and time zones

- Calendar maths (`addDays`, `daysBetween`) works on UTC day numbers built from the
  `YYYY-MM-DD` parts. `new Date('2026-12-11')` is never used, because it means UTC
  midnight and shows as 10 December west of UTC.
- "Today" is computed in the deadline's own time zone with `Intl.DateTimeFormat`.
- `zonedDateTimeToEpoch` converts a wall-clock time in a zone to an instant, computing
  the offset twice to handle daylight-saving changes.
- A date-only deadline is overdue from the next day; a timed one from that minute.

## Reminders

Reminder planning is pure (`services/reminders.js`); orchestration lives in
`background/reminder-runner.js`, which receives every Chrome API as a parameter so the
whole flow is unit-tested with mocks (`tests/reminder-runner.test.js`). The service
worker only wires events to the runner. Reminder bookkeeping is stored under its own
`reminderState` key, so reminder activity never rewrites deadline records.

**Identifiers.** `dr:<deadline id>:<minutes before>` per reminder,
`dr-snooze:<deadline id>` per snooze, `dr-refresh` for the next local midnight or the
next timed deadline (badge and "overdue" roll-over). A reminder's dedupe key is
`<id>:<offset>:<epoch ms>`, so a changed due date produces a new key.

**Reconcile** runs on install, update, browser start-up, every relevant storage change,
late alarms and the refresh alarm: summarise missed reminders, drop ended snoozes,
`syncAlarms` (create missing, clear stale, never touch other alarms), update the badge,
and record `lastCheckedAt`.

**Timing rules.**

- Whole-day offsets on a date-only deadline fire at the configured reminder time
  (default 09:00) on that day; on a timed deadline they keep the deadline's time of day.
- "On the deadline day" fires at the reminder time, or 30 minutes before a deadline that
  is earlier than that.
- Offsets under a day need a submission time; date-only deadlines skip them.
- Times are computed in each deadline's own time zone with `Intl`, so DST and the
  computer's time zone do not move them.
- At most 400 alarms (Chrome allows 500), soonest first.

**Delivery.** An alarm more than 10 minutes late (sleep, closed browser) is not shown as
if on time; reconcile turns everything missed since `lastCheckedAt` (at most 3 days)
into one notice per deadline, or one summary for several. Fired keys are stored (60-day
retention), and each deadline has one notification id (`dr-n:<id>`), so duplicates are
replaced rather than stacked. Buttons: Mark complete, Snooze (setting: 1 h / 3 h / 1 day).
Clicking opens `dashboard.html#deadline=<id>`.

**Badge.** `badgeFor(summary, mode)` → text, colour (red when anything is overdue) and a
tooltip that always lists overdue, due-soon and upcoming counts in words.

## Documents

Stage 2 import is described in detail in [DOCUMENT_IMPORT.md](DOCUMENT_IMPORT.md). In short:

- Files are checked before any parser runs (`documents/file-checks.js`), hashed with
  SHA-256, read by PDF.js or Mammoth (in workers), and passed as plain text blocks with
  page/paragraph references to the pure extraction engine.
- The engine returns candidates; nothing is saved until the user confirms the review.
- `services/duplicates.js` matches the hash and the candidates against the library;
  `compareWithExtraction` / `applyDocumentChanges` merge an updated brief into an
  existing deadline, never pre-selecting fields in `confirmedFields` and always keeping
  notes, completion, checklist progress and reminders.
- Library records hold metadata, warnings and evidence quotes (≈ 4 KB each). Original
  files are kept only on request, in IndexedDB.

## UI

- Built with small DOM helpers (`h()`); all text is set with text nodes. Nothing uses
  `innerHTML`, and a test enforces this.
- Lists render with one delegated click handler. Cards are cached by record object and
  only rebuilt when the record or the day changes.
- Dialogs use native `<dialog>` with `showModal()` (focus trap, Escape, inert
  background), labelled titles and focus restoration.
- Colours are `light-dark()` token pairs. `<html data-theme>` forces light or dark;
  without it the system preference applies. `prefers-reduced-motion` disables motion.
- Urgency is shown with text and an icon as well as colour.

## Security

- MV3 CSP: `script-src 'self'; object-src 'self'`. No inline scripts (verified after
  each build), no remote code, no `eval`.
- Submission links must be `http(s)`; they open with `rel="noopener noreferrer"`.
- Backups are parsed as JSON and normalised record by record before they are written.

## Design decisions

| Decision                                 | Reason                                                                             |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| No framework                             | The UI is small; plain modules keep the popup fast and the bundle tiny.            |
| One `assessments` array                  | Simple, atomic writes; expected data size is small (hundreds of items).            |
| `light-dark()` tokens                    | One token set for both themes; needs Chrome/Edge 123+ (`minimum_chrome_version`).  |
| `alarms` + `notifications` now           | Reminders are a core requirement for manual deadlines; no host access is needed.   |
| Calendar date strings                    | Avoids the classic UTC off-by-one-day bug for date-only deadlines.                 |
| Metadata-only document links             | Keeps storage small; full text is never stored, only short evidence quotes.        |
| PDF.js + Mammoth, lazy-loaded            | Mature, MIT/Apache/BSD libraries; loaded only on the import page, never the popup. |
| Mammoth's document tree, not its HTML    | Structure without injecting or sanitising generated HTML.                          |
| Workers for parsing                      | Keeps the page responsive; terminating the worker enforces cancel and time limits. |
| Rule-based extraction                    | Deterministic, explainable confidence and evidence; no AI or network.              |
| Own ZIP inspection + DecompressionStream | Archive-bomb protection before Mammoth inflates anything.                          |
